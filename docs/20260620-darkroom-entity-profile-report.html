Darkroom 人物档案与实体关系网络改造报告

生成时间：2026-06-20  |  范围：Darkroom Chat 记忆系统人物/实体管理全流程改造

一、改造目标

把 Darkroom 的记忆管理从「零散提及」升级为「围绕人物的档案系统」：

  • 覆盖所有人物实体：酒吧已知人物、已识别用户、用户提到的第三方
  • 把记忆挂接到实体，支持按人物召回
  • 建立人物关系图（friend / partner / colleague / ex / sibling / knows / mentioned_with）
  • 聊天时针对提到的人物注入「人物卡」
  • 保留隐私控制：第三方档案 TTL、用户可要求被遗忘

二、Phase 1：数据层升级

新增/修改的表

  1. darkroom_entities（扩展）
    • 新增 entity_type、profile (JSONB)、mention_count、first_seen_at、last_mentioned_at
    • profile 包含 description、preferences、known_facts、relationship_hints、confidence、privacy 等
  2. darkroom_memory_entities（新建）：关联记忆与实体，role 包含 subject / object / co_mention / mentioned
  3. darkroom_entity_relations（新建）：人物关系边

迁移结果

运行 scripts/seed-known-entities-to-db.ts 后：

  • 698 条记忆被扫描，106 条与实体建立关联

三、Phase 2：提取层增强

  • lib/darkroom-chat.ts 新增 extractEntitiesFromText(text, isZh)，识别自然提及并过滤 MBTI、停用词
  • data/darkroom-messages-zh.json / -messages.json 的 extractionPrompt 要求 LLM 返回 memories + entities + relations，同时兼容旧格式
  • app/api/darkroom/extract/route.ts 解析新格式、写入实体/关系/关联，并注入已知实体别名提示（老王 → Tee）

四、Phase 3：聊天层人物卡

  • lib/darkroom-memory.ts 新增 buildEntityCard(...)
  • app/api/darkroom/chat/route.ts 识别话题实体，最多生成 2 张人物卡注入 prompt，并优先召回实体关联记忆
  • lib/darkroom-budget.ts 新增 entityCards 字段，预算紧张时人物卡优先于无关 memory 保留

五、Phase 4：Profile 自动聚合

  • 新建 lib/darkroom-entity-summary.ts：summarizeEntityProfile(entityId, isZh) 与 summarizeAllEntityProfiles(...)
  • 新建 scripts/summarize-entity-profiles.ts 脚本
  • 摘要字段：description、preferences、known_facts、relationship_hints、confidence

运行方式（需要 DEEPSEEK_API_KEY）：

export DEEPSEEK_API_KEY=...
npx tsx --env-file=.env.local scripts/summarize-entity-profiles.ts

建议先小批量试运行：

SUMMARIZE_LIMIT=5 SUMMARIZE_MIN_MENTIONS=3 npx tsx --env-file=.env.local scripts/summarize-entity-profiles.ts

六、Phase 5：隐私与降级

  • 新 user_mentioned 实体默认写入 privacy: { consent: "implicit", ttl_days: 90, sensitive: false }
  • forgetEntity(name)：标记 declined、清空 profile、删除关系
  • pruneExpiredEntityProfiles(90)：清理过期第三方档案
  • detectForgetRequest(message, isZh) 识别「忘了我」「别提小马了」「Forget about me」等
  • 聊天 route 检测到遗忘请求后立即清除并返回确认

八、需要你人工检查确认的信息

  • 已知实体描述是否准确：检查 11 个 knowledge_base 实体的 profile.description，来源是 KNOWN_ENTITIES 的 zhHint/enHint，有误请改 JSON 后重新迁移。
  • 记忆关联是否张冠李戴：抽查 darkroom_memory_entities 表，确认无错误关联。
  • 人物卡注入后的回复风格：部署后测试聊到「小马」「阿林」等人物，确认 AI 基于档案回复、不编造。
  • LLM 自动摘要的可信度：运行 summarize-entity-profiles.ts 后抽查 entity.profile，低 confidence 要人工复核。
  • 「遗忘」指令是否符合预期：测试「忘了我」「别提小明了」，确认只清除 profile/关系、保留名字的软删除程度足够。

九、推荐后续操作

  1. 本地/生产部署前再次验证：
    npm run typecheck && npm run test && npm run build
  2. 部署后观察 Vercel log：
    [darkroom:extract] batch=... raw_memories=... entities=... relations=...
  3. 运行 profile 聚合前，先小批量测试。
  4. 如需定时 TTL 清理，可配置 Vercel Cron 或本地定时任务。
