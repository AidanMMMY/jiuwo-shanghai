Special Event 模块 — 内容管理指南

JIUWO Shanghai · 2026-06-06 · Module Design

1. 核心原则

新模块下，一切围绕 data/events.json 展开。只需要改一个 JSON 数组 + 上传海报图，路由和页面全部由代码动态生成，无需碰任何 .tsx 文件。

data/events.json

← 所有活动的唯一数据源（新建 / 修改 / 归档都在这里）

data/site.json

← 只控制首页入口开关 + 无活动时的fallback 文案

public/images/events/

← 海报图文件夹（按 slug 命名，小写扩展名）

app/(en)/special/[slug]/page.tsx

← 动态路由，无需手动创建

2. 文件结构总览

# 数据层
data/
  events.json          ← 所有活动的唯一数据源
  site.json            ← 入口开关 + fallback 文案

# 路由（动态生成，无需手动创建）
app/
  (en)/special/[slug]/page.tsx   ← EN 活动详情页
  zh/special/[slug]/page.tsx     ← ZH 活动详情页
  (en)/special/page.tsx          ← 入口网关（自动判断跳哪个）
  zh/special/page.tsx

# 图片
public/images/events/
  event-20260605.webp      ← 按 slug 命名，小写扩展名
  event-20260718.webp      ← 下一个活动

3. 日常操作指南

1 发布一个新活动

Step 1：上传海报图到 public/images/events/（建议 3:4 竖版，.webp 或 .jpg，小写扩展名）

Step 2：在 data/events.json 的 events 数组最前面插入新对象：

{
  "slug": "event-20260718",
  "title": "One Night Host",
  "titleZh": "一日店长接管",
  "label": "July 18",
  "labelZh": "7月18日",
  "hostName": "Alex",
  "date": "2026-07-18",
  "dateDisplay": "Saturday, July 18 · 8pm",
  "dateDisplayZh": "7月18日 周六 · 晚8点",
  "description": "Guest bartender Alex from Tokyo …",
  "descriptionZh": "来自东京的客座调酒师 Alex …",
  "subtitle": "Tokyo Meets Shanghai",
  "subtitleZh": "东京遇见上海",
  "poster": "/images/events/event-20260718.webp",
  "venue": "Julu Rd. 397",
  "venueZh": "巨鹿路397号",
  "rsvpEnabled": true,
  "retrospective": "",
  "retrospectiveZh": "",
  "retrospectivePhotos": []
}

系统自动行为：

→ /special 自动 redirect 到 /special/event-20260718

→ 首页 HeroCarousel 卡片显示「July 18」+「Alex」，可点击进入详情

→ RSVP 系统自动使用新 slug event-20260718 创建独立报名表

→ Sitemap 自动包含新页面

Step 3：确认 data/site.json 中 specialEvent.enabled = true，然后 git commit + push → Vercel 自动部署。

⚠️ 注意事项：

· date 必须是 YYYY-MM-DD 格式，这是判定 upcoming/past 的唯一依据

· slug 建议遵循 event-YYYYMMDD 或 event-YYYYMMDD-hostname 约定

· poster 图片建议 3:4 竖版，必须小写扩展名（否则构建失败）

2 活动结束后添加回顾内容

活动日期一过，系统自动将状态从 upcoming 切换为 past。此时编辑 events.json 中对应活动的 retrospective 字段：

{
  "slug": "event-20260605",
  // …其他字段不变…
  "retrospective": "What a night! Owen brought the energy of Roland Garros to JIUWO. The tennis crowd showed up in full force, and the French Open-themed cocktails were a hit. 🎾🍸",
  "retrospectiveZh": "难忘的一晚！Owen 把法网的热情带到了啾喔。网球圈的朋友们齐聚一堂，法网主题鸡尾酒大受欢迎。🎾🍸",
  "retrospectivePhotos": [
    "/images/events/event-20260605-recap-1.webp",
    "/images/events/event-20260605-recap-2.webp",
    "/images/events/event-20260605-recap-3.webp"
  ]
}

系统自动行为：

→ RSVP 报名按钮消失 → 之前报名的人显示为「到场的朋友」名单（只读）

→ retrospective 内容在「活动回顾」区域展示

→ retrospectivePhotos 以 2 列网格展示

→ 该活动自动出现在 /special 往期回顾网格中

3 活动已结束但还没写回顾

这是过渡状态，无需任何操作：

  • 活动日期过了 → 自动判定为 past
  • 页面显示历史 RSVP 名单（谁来了）
  • 不显示回顾内容区域（因为 retrospective 还是空字符串）

等你有空时，直接编辑 events.json 加上回顾内容即可，无需改其他文件。

4 临时关闭首页入口

如果一段时间内没有 upcoming 活动，有两种选择：

A. 完全关闭（不展示卡片）

编辑 data/site.json：

"specialEvent": {
  "enabled": false,
  …
}

HeroCarousel 完全不渲染 special event 卡片，首页恢复纯 hero 模式。

B. 展示往期回顾入口

"specialEvent": {
  "enabled": true,
  "heroFallback": "Past Events Memories",
  "heroFallbackZh": "往期活动回顾",
  …
}

首页卡片显示「Past Events Memories」+「VIEW DETAILS」，点击进入往期回顾列表。

5 某个活动不需要 RSVP

创建活动时设置 "rsvpEnabled": false，活动页面不渲染报名按钮和名单区域，只展示海报和活动信息。

4. 字段对照表

字段用途何时需要修改
slugURL 路径 + RSVP 标识 + localStorage key创建时确定，之后不变
title / titleZh活动标题（海报上的大字）创建时确定
label / labelZh首页卡片第一行文字创建时确定
hostName嘉宾名（首页卡片第二行 + 海报金色大字）创建时确定
dateISO 日期 YYYY-MM-DD创建时确定，判定 upcoming/past 的唯一依据
dateDisplay / dateDisplayZh海报底部日期展示文字创建时确定
description / descriptionZh活动描述正文创建时确定
subtitle / subtitleZh描述区粗体副标题创建时确定
poster海报图路径创建时确定
venue / venueZh场地信息一般不变
rsvpEnabled是否开放报名创建时确定；活动结束后可改为 false
retrospective / retrospectiveZh回顾文案活动结束后追加
retrospectivePhotos回顾照片数组活动结束后追加

5. 入口路由逻辑

首页 HeroCarousel 卡片 → site.specialEvent.enabled? → 有 upcoming? → 是 → /special/{slug}
活动详情 + RSVP → 否 → /special
往期回顾列表

/special 的智能网关逻辑：

1. 查询 events.json 中所有 date >= today 的活动

2. 若有 → permanentRedirect(/special/{slug})

3. 若无 → 渲染 PastEventsGrid（往期回顾卡片网格）

6. 日常维护速查

操作步骤
新增活动 ① 上传海报 → public/images/events/
② events.json 数组最前面插入新对象
③ 确认 site.json 中 enabled: true
④ git commit + push → Vercel 自动部署
活动结束 ① 不用动（自动变 past，首页入口自动消失）
② 想加回顾 → 编辑 retrospective 字段 + 上传回顾照片
修改已有活动 直接改 events.json 中对应该活动的对象
Vercel 自动部署生效
删除活动 从 events.json 数组中移除该对象即可
（建议保留记录，宁可删也不要留错误数据）
临时关闭入口 site.json → specialEvent.enabled: false

7. 页面渲染模式对照

条件渲染模式显示内容
isUpcoming + rsvpEnabled RSVP 模式 海报 + 标题/嘉宾 +「我要来」按钮 + 报名名单 + RSVP modal
isUpcoming + !rsvpEnabled 纯展示模式 海报 + 标题/嘉宾 + 日期场地（无 RSVP 区域）
!isUpcoming + 有 retrospective 回顾模式 海报 +「到场的朋友」名单 + 回顾文章 + 回顾照片网格
!isUpcoming + 无 retrospective 过渡模式 海报 +「到场的朋友」名单（回顾区域不渲染）
